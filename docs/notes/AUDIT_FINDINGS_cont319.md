## 5. [MED] gates-correctness — scripts/qa/eyes_gold_gate.py:39-40, :80
**Issue:** The gate has no per-instance 'gripped count == expected cube count' check, so a partial where ONE cube GRIP-SLIPPED (finger-contact but object NEVER LIFTED/held) is invisible. scene_eyes writes that as 'CONVERGED + GRIP-SLIP (... NEVER LIFTED, not held)' (scene_eyes.py:1079), which is neither a 'never-gripped' token nor a 'CONVERGED + GRIPPED' token, so it is counted as neither a reject nor a success. If any OTHER cube succeeded (gripped>=1, never==0), the bin/grid branch passes and the slipped cube — which was never transported — is silently accepted.
**Fix:** Count 'GRIP-SLIP'/'NEVER LIFTED' occurrences and treat them as ungripped (reject), same class as never-gripped. Additionally enforce gripped == number of claimed delivery cubes per instance (require the template's expected cube count and assert all gripped+placed).

## 17. [LOW] real-asset-recipes — scripts/qa/real_asset_spawn.py:86
**Issue:** compute_spawn_recipe's standing-rotation base offset assumes origin-centered geometry: `base_off = (-ez/2.0) if rotation else min_z` (line 86). This is correct for the YCB Axis_Aligned family (verified centers ~[0,0,0]) but would mis-place any non-origin-centered asset after a stand-up rotation, spawning it intersecting or floating above the surface. The non-rotated path correctly uses the measured min_z; the rotated path discards the actual post-rotation base and substitutes -ez/2. The helper is advertised for 'ANY real asset' so this latent assumption matters for non-YCB assets.
**Fix:** For a stand-up rotation about X/Y, derive the new base from the native bbox extreme that rotates to -Z (e.g. for [90,0,0] the new base = -max_y of the native bbox), not -ez/2; this is robust to non-centered origins.
