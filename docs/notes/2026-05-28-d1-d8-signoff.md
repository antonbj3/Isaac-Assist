## D1 — Adopt `<domain>.<robot>.<variant>.NNN` id scheme + 12-domain enum
- **Choice**: (a) Adopt as-is.
- **Why**: Flat-with-dots is grep- and Chroma-safe. 12 domains map onto existing `pattern_hint` axis so no new taxonomy axis is introduced. Option (c) (keep CP-NN, bolt on index_card) collapses the moment CP-NEW yrkesroll names appear — already happening on `feat/multimodal-foundation`.
- **Unblocks**: D2 migration order, rename script (action 4-5), legacy_id_map shim, every downstream id-aware lint.

## D2 — Migration order: Cohort B (CP-*) first
- **Choice**: (a) B first, then A (dialog), then canary.
- **Why**: Function-gate is the regression signal for B; canary-first would leave us blind during the riskiest rename. Source doc's compromise (rename canary on a parallel branch the day before B lands) is accepted as the mitigation.
- **Unblocks**: D8 timing (Cohort B finish → W1 start); avoids canary going silent during B-rename.

## D3 — `evaluate_candidates` model: Haiku 4.6
- **Choice**: (a) Haiku 4.6 (~$0.001/call, ~300 ms).
- **Why**: Latency budget dominates per-call cost at our funnel volume. phi4 adds ~200 ms and a local-only failure mode that breaks the funnel when the box is busy with Isaac Sim. Gemini Flash saves $0.0005/call — not worth the second vendor for medium-confidence path.
- **Reservation**: revisit if monthly spend on this path exceeds **$50** (source doc threshold) — log to LLM-spend monitor.
- **Unblocks**: planner/router.py medium-confidence branch ships without a model-choice blocker.

## D4 — HIL UI surface: BOTH TUI and Canvas SPA
- **Choice**: (c) Both behind the same `/hil/*` backend.
- **Why**: Backend route is the only new code either way. TUI ships now and is the fallback when SPA isn't running. SPA is the operator surface for Phase 24b. Picking one would force a future rewrite or block operators when the other path is down.
- **Unblocks**: HIL backend route in W1 success metrics; smoke-test HIL-2 question observable.

## D5 — Confidence-floor defaults: accept proposed per-modality values
- **Choice**: (a) text 0.7 / voice 0.6 / sketch 0.5 / photo 0.4 / drag-drop 1.0.
- **Why**: Values are calibrated against actual `MULTIMODAL_TEXT_INTENT=soft` behavior — not a guess. Single-floor 0.6 (option b) wastes signal on drag-drop. Tighter values (option c) over-trigger HIL on sketches/photos where confidence is inherently lower.
- **Reservation**: re-tune from observed HIL skip rates after **50 sessions** (source doc cadence) — applies to all modalities, not just outliers.
- **Unblocks**: HIL trigger logic, soft-filter threshold wiring in funnel.

## D6 — Composition: Mode A workflows first
- **Choice**: (a) Mode A first, Mode B later.
- **Why**: Mode B requires `template.outputs` schema across all CP-* — multi-week schema migration that would collide with the Cohort B rename. Mode A registers 3 existing workflow templates in ≤30 LOC. Source doc §1 contradiction reconciliation (integration's workflow-as-first-class-candidate path) is the right Mode-A shape.
- **Unblocks**: workflow_registry.py (action 9), funnel surfaces workflows alongside templates.

## D7 — Variant generator gate: form-gate per child + function-gate on base
- **Choice**: (a) Form-gate every child, function-gate on the base.
- **Why**: §5 tier table assumes this. Function-gate per child is the 500 h infeasibility flagged in roadmap. Option (c) (trust the parent) silently corrupts T0 — unacceptable per `feedback_diagnostic_first_then_fix` (verify, don't assume).
- **Unblocks**: variant generator hitting ≥30 children per base in W1 success metric.

## D8 — Migration vs W1: finish Cohort B rename FIRST
- **Choice**: (a) Finish Cohort B rename, then start W1.
- **Why**: Risk register flags "taxonomy migration coincides with expansion" as the highest-impact failure mode. Id-scheme freeze before waves is non-negotiable — running W1 on legacy CP-NN (option b) creates a second rename event mid-wave; option (c) (new files new naming, old files old) forks the index. W1 reroute is small.
- **Unblocks**: W1 starts on a frozen id-scheme; rename_canonicals.py becomes a one-shot, not a recurring chore.
